# 最好的狼人杀

一个面向线下狼人杀场景的轻量辅助工具。项目通过 PeerJS/WebRTC 建立点对点连接，集中完成房间创建、自由排座、私密发牌和上帝记牌，不自动执行角色技能或胜负判定。

在线体验：[https://friends233.github.io/best-werewolf/](https://friends233.github.io/best-werewolf/)

## 主要功能

- 使用四位房间码加入房间，也可以通过二维码分享邀请链接。
- 支持 4–12 人局，并允许上帝在房间内调整不同身份牌的数量。
- 玩家可自动补位或主动选择空位；上帝可以交换任意两个座位。
- 房主和玩家都可以申请上帝位，上帝本人也可以同时参与游戏。
- 洗牌后将身份单独发送给对应玩家，广播的房间状态不包含真实身份。
- 上帝视角展示全场身份，并可标记存活、夜死、放逐及自定义状态标签。
- 玩家身份卡支持翻转查看和再次隐藏。
- 支持保留玩家和座位直接开始下一局。
- 内置 21 种常见角色配置；角色数量、名称和简介集中在 `src/config/roles.ts` 中维护。

## 使用流程

1. 创建者输入昵称，选择身份牌及数量后创建房间。
2. 其他玩家通过四位房间码或二维码进入，并输入昵称。
3. 一名玩家坐上上帝位，检查人数、身份配置和座位。
4. 所有座位坐满后，上帝点击“确认发牌”。
5. 玩家点击身份卡查看自己的角色，上帝在面板中记录游戏状态。
6. 本局结束后，上帝点击“重开”，保留当前玩家与座位并重新等待发牌。

创建者需要保持房间页面打开。房间关闭后，其他玩家无法继续与房主同步。

## 技术架构

项目采用星型 P2P 通信：房主页面保存权威游戏状态，每位玩家分别与房主建立 WebRTC 数据通道。

```text
                           ┌────────────────────┐
                           │       房主端       │
                           │ 房间状态 / 座位    │
                           │ 洗牌 / 发牌 / 重置 │
                           └─────────┬──────────┘
                                     │ PeerJS / WebRTC
                 ┌───────────────────┼───────────────────┐
                 │                   │                   │
          ┌──────▼──────┐     ┌──────▼──────┐     ┌──────▼──────┐
          │   玩家 A    │     │   玩家 B    │     │   玩家 N    │
          │ 接收自己的牌 │     │ 接收自己的牌 │     │ 接收自己的牌 │
          └─────────────┘     └─────────────┘     └─────────────┘
```

房主广播的 `SYNC_ROOM_STATE` 会移除座位上的 `roleId`。每位玩家的身份通过单独的 `ASSIGN_ROLE` 消息发送；上帝设备则通过 `SYNC_GOD_STATE` 获取完整状态。

主要模块：

| 路径 | 职责 |
| --- | --- |
| `src/App.tsx` | 首页、房主会话和玩家会话切换 |
| `src/hooks/usePeerHost.ts` | 房主端状态机、连接管理、排座与发牌 |
| `src/hooks/usePeerClient.ts` | 玩家连接、状态订阅与身份接收 |
| `src/types/protocol.ts` | P2P 消息、房间状态和座位类型 |
| `src/config/roles.ts` | 角色注册表、阵营与展示信息 |
| `src/components/` | 首页、房间、座位、身份卡和角色配置界面 |
| `src/utils/game.ts` | 房间码、座位、洗牌等基础逻辑 |

## 本地开发

环境要求：Node.js 20 或兼容版本、npm。

```bash
npm ci
npm run dev
```

开发服务器默认监听 `0.0.0.0`。同一局域网内的设备可以通过终端输出的网络地址访问，也可以部署到支持 HTTPS 的静态站点后通过邀请链接加入。

### 测试模式

在房主页面地址后添加 `?debug=1` 即可开启测试模式，例如：

```text
http://localhost:5173/?debug=1
```

测试模式只在房主端生效。房主可以一次添加或补满模拟玩家，发牌后通过测试面板自由切换不同玩家的身份视角；切换后，座位与预选操作也会使用对应玩家的身份。模拟玩家不会建立额外的设备连接，去掉 `debug=1` 并刷新后会从房间中清理。

生产构建：

```bash
npm run build
npm run preview
```

构建结果输出到 `dist/`。`vite.config.ts` 当前将生产环境资源路径设置为 `/best-werewolf/`；如果仓库或部署路径发生变化，需要同步修改其中的 `base`。

## 角色配置

当前角色分为以下两类：

- 好人阵营：普通村民、预言家、女巫、猎人、守卫、白痴、骑士、守墓人、摄梦人、魔术师、猎魔人、通灵师。
- 狼人阵营：普通狼人、白狼王、狼王、狼美人、石像鬼、恶灵骑士、隐狼、血月使徒、机械狼。

默认板子为 2 名普通狼人、2 名普通村民、1 名预言家和 1 名女巫。除普通村民和普通狼人外，其他角色当前均限制为最多 1 张。

## 当前边界

- 项目负责发牌和记录，不自动处理夜间行动、投票、角色技能、发言顺序或胜负判定。
- 角色简介只用于身份展示，并不代表对应技能已经由程序执行。
- 房间使用 PeerJS 的公共信令服务建立连接，因此“无后端”指无需自建业务服务，并非完全不依赖网络服务。
- 房主页面是单点权威状态源；房主退出后，房间连接和后续同步会中断。
- 房间码是当前的加入凭证，没有密码或账号鉴权。请勿在公开场合分享无关人员的房间二维码。
- 目前只有普通狼人配置了角色原画，其他角色使用占位卡面。
- 工程暂未配置自动化测试和 GitHub Actions 部署流程。

更完整的产品和技术设计方案见 [`best-werewolf.md`](./best-werewolf.md)。
